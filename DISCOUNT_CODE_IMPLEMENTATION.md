## 1. How Bulk Student Discounts Work

### 1.1 The Business Process

**Scenario:**  
A school wants to enroll 100 students in a Python programming course.

| Current Process | With Bulk Discount |
|-----------------|-------------------|
| Each student pays full price individually | School gets discount code for bulk registration |
| 100 separate transactions | One bulk order, all students get access |
| High friction for institutional buyers | Simple, streamlined procurement |
| No incentive for bulk purchases | Competitive pricing for volume |

### 1.2 How It Works (From Organization's View)

1. **Organization requests bulk enrollment** → Sales team contacts them with a quote
2. **Custom discount code generated** → Valid for 30-90 days, specific to their organization
3. **Organization shares code with students** → Students enter code during enrollment
4. **Automatic discount applied** → Each student gets the agreed discount
5. **Simple payment** → Students pay discounted price for course access
6. **Tracking & reporting** → Organization sees analytics on student progress

### 1.3 Example Pricing

**Course: Advanced Python (Original Price: $500 per student)**

| Scenario | Price per Student | Total for 100 | Savings |
|----------|------------------|---------------|---------|
| Single student (no discount) | $500 | $50,000 | — |
| School bulk (20% discount) | $400 | $40,000 | $10,000 |
| Corporation bulk (30% discount) | $350 | $35,000 | $15,000 |

The organization gets better pricing, and we capture institutional revenue that wouldn't happen otherwise.

## 4. How It Works - Step by Step

### 4.1 Sales Process

**Step 1: Organization Requests Bulk Enrollment**
- Organization contacts sales team
- Says: "We want 100+ students in Python course"
- Sales discusses budget and timeline

**Step 2: Create Custom Discount Code**
- Sales team generates unique code (e.g., "UNIVERSITY2026-PYTHON")
- Sets discount (e.g., 25%)
- Sets validity period (e.g., 90 days)
- Sets usage limit (e.g., 120 uses for 100+ students buffer)
- Sends code and enrollment link to organization

**Step 3: Organization Shares with Students**
- Organization sends email to students with:
  - Course link
  - Discount code
  - Registration deadline
  - Special instructions

**Step 4: Students Enroll**
- Student clicks link → Course page
- Student enters discount code
- System shows discount (e.g., "20% off - Save $10")
- Student pays discounted price
- Instant course access

**Step 5: Track Progress**
- Organization sees dashboard with:
  - All enrolled students
  - Who has started course
  - Who completed lessons
  - Who earned certificates
  - Overall completion rates

### 4.2 Dashboard for Management

**For Sales/Account Teams:**
- Generate new discount codes (2 clicks)
- View code status (active, expired, used X/max)
- See revenue generated per code
- Track which organizations used codes
- Download usage reports

**For Finance:**
- See total revenue from bulk discounts
- Compare bulk vs. individual revenue
- Track average discount rates
- See redemption rates
- Forecast bulk revenue

**For Customer Success:**
- Monitor student progress by organization
- See completion rates
- Identify struggling students
- Send targeted help/resources

## 11. Q&A with Leadership

**Q: Why not just offer discounts without tracking?**  
A: Tracking creates value - organizations see ROI and renew. It also prevents abuse.

**Q: What if an organization never enrolls students?**  
A: Offer refund/credit. Set expectation upfront. Create a 30-day enrollment minimum.

**Q: Will this hurt our regular student pricing?**  
A: No. Most institutions wouldn't have bought anyway. Volume makes up difference. Plus, bulk students often lead to individual sign-ups.

**Q: How do we prevent one person from reselling the discount?**  
A: Code limit enforcement + monitoring + terms of service.

**Q: Can students use a discount code twice?**  
A: No. One student, one code, one course = one-time use. Prevents fraud.

**Q: What if we exceed development budget?**  
A: Scope is flexible. We can defer dashboard features (Phase 2) and launch basic version first.
